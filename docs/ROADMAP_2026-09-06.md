## Regra de sequência

A partir deste snapshot, nenhuma optimização substantiva de Ares pode ultrapassar os gates de correctness abaixo.

```text
C0 state identity
→ C1 canonical action
→ C2 execution
→ C3 independent legal-action oracle
→ C4 cross-backend transition equivalence
→ C5 bridge/protocol
→ pure node-budget semantics
→ A0 PASS
→ Strength calibration
→ contextual balance
→ search / move ordering / NNUE
```

## Gate 0 — fechar A0

### Bloqueadores

- [x] C4 cobertura explícita de timers/lifecycle/TWC/effects/spawn-cooldown/special-spells/terminal transitions.
- [x] comparação pós-ação Python/C++ em cada passo nos casos críticos.
- [x] make→undo→root exact restoration onde aplicável.
- [x] demonstrar `go nodes N` sem dependência semântica oculta de wall-clock.
- [x] produzir um veredito agregado `A0 = PASS | PARTIAL | BLOCKED`.

### Veredito

**A0 = PASS** em 2026-09-07, com escopo limitado à fundação de correctness Python/C++, C0-C5 e semântica de orçamento fixo por nós documentada em `docs/A0_VERDICT_2026-09-07.md`.

### Não permitido antes de A0 PASS

- promover NNUE como melhoria de força;
- alterar evaluation por alegado ganho global;
- promover selective search/move ordering com base apenas em puzzles;
- usar benchmark dirigido como prova de strength.

O gate A0 está agora fechado; estas restrições deixam de bloquear o início formal da fase de Strength, mas os seus princípios metodológicos continuam obrigatórios.

## Gate 1 — Strength

A próxima fase começa por:

```text
A/A neutrality
→ weaker/stronger controls
→ replicated runs
→ true experimental units
→ contextual coverage
→ calibrated uncertainty
→ SPRT operating characteristics
→ independent promotion gate
```

O hold-out protegido não pode orientar tuning.

## Gate 2 — UI

UI pode avançar em paralelo quando a alteração não muda regras, transições ou contratos C0–C5. A validação visual deve continuar separada de correctness e CI.

## Gate 3 — documentação

Cada marco deve actualizar snapshot/roadmap no mesmo bloco documental. Um snapshot antigo nunca deve ser usado para inferir o estado atual do `main`.

## Anti-regressão metodológica

```text
CI verde ≠ correctness total
C3 ≠ C4
C4 ≠ search quality
search quality ≠ strength
benchmark ≠ global gain
snapshot ≠ source of truth if stale
A0 PASS ≠ strength proven
```

Ver `docs/A0_VERDICT_2026-09-07.md` e `docs/STATE_AND_CRITIQUE_2026-09-06.md` para a fundamentação do gate.
