# Decision — FrostMage Nevada semantic contract

**Date:** 2026-08-28  
**Status:** In implementation

## Problem discovered by manual play

FrostMage's Nevada was exposed as a conditional stun: move generation required an enemy to be present in the affected cross. That was inconsistent with the intended area-spell semantics and caused the player-facing game to stop offering Nevada in legal empty areas.

The same change also affects cross-backend move generation, perft, make/unmake, replay evidence and UI interpretation. The correct response is to update the implementation contract and the tests, not to remove differential coverage.

## Authoritative contract

Nevada is a selectable area spell:

- the FrostMage must be able to act;
- the selected center is any board square within Manhattan distance 3 of the FrostMage;
- the center must not already contain an ice effect;
- an enemy is not required in the affected cross;
- Nevada has no charges and no cooldown;
- therefore a FrostMage can cast Nevada on consecutive turns whenever it receives another turn and chooses a legal center;
- the center becomes an ice tile;
- ice prevents movement onto and through the tile;
- ice also prevents using the tile as a spell center;
- enemies on eligible cells of the cross receive the existing stun/second-hit elimination semantics;
- an opposing Inquisitor's silence still prevents the spell.

## Backend invariant

Python and C++ are independent implementations of the same rules. The same Nevada center set must therefore be generated by both backends for the same position, subject only to representation differences.

The C++ `Move` representation for Nevada is `SPELL` with `spell_name=nevada`. The old FrostMage-specific `STUN` move is no longer the public representation of Nevada.

## Test policy

Tests that described the old public FrostMage `STUN` action are migrated to `SPELL/nevada`. Differential move-generation and perft tests remain mandatory and must pass against the new semantics. A failure between Python and C++ is treated as an implementation defect, not as a reason to weaken the test.

Coverage should explicitly include empty legal centers, ice-center exclusion, silence, make/unmake restoration and second-hit elimination.

## Replay implications

The canonical replay records executed semantic actions. Engine diagnostics may record accepted/rejected action attempts. Developer UI replay records what choices were actually exposed to the player.

Therefore:

```text
no Nevada in canonical replay
```

must not be interpreted as:

```text
player deliberately chose not to cast Nevada
```

unless the developer UI evidence shows that Nevada was actually available at that decision point.

## Related observations

Manual play also exposed a separate UX issue: when the same destination can represent more than one legal action, the UI must not silently prefer movement. It must present the legal action choices. This is a generic interaction rule and should be tested independently from FrostMage.
